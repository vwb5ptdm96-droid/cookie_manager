## 0. 产品一句话

单台 Windows 内部运维台：维护下游采集依赖的电商/内容平台 **Session/Cookie 长期可用**。  
核心闭环是 **检测登录态 → 自动刷新或扩展补采 → 失败可追踪（飞书 + 自动排障）**。  
外部凭证表 `ods_cookie_playwright` 由本系统读取，并在扩展采集/手动上报链路按约定写回（不重构旧表结构）。

### 0.1 Agent 维护层（排障已落地增强；值班增量 2026-09-20 锁定、实现未开始）

详见 `docs/agent/AGENT-MAINTENANCE-LAYER.md` §12、`docs/agent/SITE-OPERATOR-MATRIX.md`。

- 排障 Repairer：修复脚本 FAIL/EXCEPTION 为主；RISK 诊断-only；成功 = 健康检测复检 PASS
- 值班 Watcher：工作台早报（不飞书）；无单问答等进程内 loop
- 采集 Collector：采集失败另立 `cookie_sync` 工单；成功 = 采集复检 PASS；无映射转人工
- SRE：诊断可进工具；重启后端须工作台确认
- 过程：工作台展示思考/操作/diff（内网全文，脱敏）；对话追问默认不改脚本

## 2. 两条主闭环（功能骨架）

### 2.1 闭环 A：健康检测任务 → 本机脚本修复 →（可选）自动排障

```text
定时/手动检测 ods_cookie_playwright
  → PASS：记状态与日志
  → FAIL：飞书 +（若开启自动修复）跑绑定 MAINTAIN 脚本
       → 锁 Profile → ScriptRun → Playwright
       → SUCCESS → 任务 PASS
       → FAIL / 异常 / RISK
            → 自动排障工单 + Claude Code 连 CDP（冷却/预算节流）
            → SOLVED / NEED_HUMAN（关 debug + 飞书转人工）
```

- 采集任务**不会**被健康任务自动触发（Spec OUT-010）。
- 人机验证（滑块/短信/扫码等）**不自动绕过**（OUT-004/012）。

### 2.2 闭环 B：Cookie 采集任务 → 同事扩展补采

```text
定时/手动检测旧 cookie
  → FAIL → 映射表反查 (worker_id, domain)
  → 派扩展 job → 上报 cookie → 写回旧表 → 复检
  → 无映射 / 超时 / 复检失败 → FAIL + 飞书
```

- 采集任务**不绑定** Profile/目录库（OUT-011）。

### 2.3 旁路 C：手动 Cookie 一键上报

独立 MV3 扩展「Cookie 一键上报」：页面悬浮球抓 cookie（+ 可选 headers）→ 手填四字段 → `POST /api/cookies/manual`。  
不经映射表、无 worker、不挂平台前端导航。

## 3. 各页面功能（对照前端现状）

### 3.1 健康检测任务 `/health-tasks`

| 能力 | 说明 |
|------|------|
| 列表/筛选 | 状态、关键字（名称/渠道/店铺/DNS/API） |
| 新增/编辑 | 检测名、URL、方法、cookie 表、channel/shop/mobile/dns、headers/body、成功/失败规则、cron、超时/重试 |
| 失败修复配置 | 自动修复开关、修复 cron、绑定脚本、运行模式、脚本配置 JSON |
| 行操作 | 编辑、**检测**、下拉：修复 / 克隆 / 删除 / 启停 |
| 时间线 | 任务维度执行时间线（API `.../timeline`） |

### 3.2 Cookie 采集任务 `/cookie-sync-tasks`

同一页通常含两块：

**采集任务**

| 能力 | 说明 |
|------|------|
| 新增/编辑/克隆/删除/启停 | 检测配置与调度类似健康任务，但失效动作为扩展采集 |
| 行操作 | 编辑、**检测**、**修复**（触发补采链路）、更多菜单 |

**采集映射**

| 能力 | 说明 |
|------|------|
| CRUD | `(worker_id, domain) → channel/shop_name/mobile_phone/dns` |

### 3.3 脚本库 `/scripts`

| 能力 | 说明 |
|------|------|
| 上传 | `.py` 脚本入库 `runtime/scripts` 体系 |
| 列表操作 | 编辑、启停、克隆/删除等 |
| 运行配置 | 关联 Profile、主文件、run-config、CDP 相关 |
| 端口状态 | 查看 CDP 端口占用情况 |

### 3.4 目录库 `/profiles`

| 能力 | 说明 |
|------|------|
| 登记/编辑/删除 | Profile key、路径（相对 `runtime/profiles` 或绝对路径）等 |
| 打开调试 / 关闭调试 | 按目录拉起/关闭可见 Chrome，暴露 CDP 端口 |
| 锁定 | **由脚本运行持有**；UI 以禁用调试等反映锁定，不提供旧「打开修复浏览器」人工工单流 |

> 后端仍保留 `lock` / `unlock` / `verify` API；产品主路径以 ScriptRun 持锁 + CDP 调试为准。

### 3.5 脚本运行 `/script-runs`

| 能力 | 说明 |
|------|------|
| 列表/刷新 | 全部或运行中实例 |
| 日志 / 结果 | 查看单次 run |
| 暂停 / 继续 / 取消 | 经 `control.json` + 进程控制 |

状态机（产品约定）：`PENDING → RUNNING → PAUSED/CANCELING → SUCCESS/FAIL/RISK/CANCELED` 等终态。

### 3.6 运行日志 `/logs`

多条件筛选运行记录并查看详情（任务/检测/脚本等相关日志，以后端 `RunLog` 字段为准）。

### 3.7 环境自检 `/environment`

执行/查看最近一次节点检查（Python、Playwright、目录、数据库、桌面会话等，项以服务实现为准）。

### 3.8 部署配置 `/deploy`

只读展示 `DEPLOY_ROOT` / `RUNTIME_ROOT`、关键子目录、API 监听与启动相关说明。

## 6. 调度与生产运行

| 组件 | 现状 |
|------|------|
| 进程内调度 | `HealthTaskScheduler`（APScheduler）：扫描健康任务 + Cookie 采集任务 |
| 生产启动 | 计划任务 **`SessionBackend-Interactive`** → `start_interactive.bat` → `run_server.py`（alembic + uvicorn） |
| 生产重启 | `restart_backend.bat`（先杀 8081 /end 任务再 /run） |
| 健康探针 | `tools/watchdog.py` + 计划任务 `SessionBackend-Watchdog` |
| 历史 NSSM | `SessionBackend` 服务**已停用**；`tools/nssm/` 仅保留说明 |
| 默认端口 | `.env` 的 `APP_PORT`（常见 **8081**）；前端 dev 常见 **5173** |
| 鉴权 | 平台 UI/主 API **无登录体系**；扩展接口 `X-API-Key` |

详细运维：`docs/OPS-STARTUP.md` / `OPS-BACKUP.md` / `OPS-MONITORING.md` / `OPS-SECURITY.md`。
