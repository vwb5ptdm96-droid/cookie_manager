# 站点值班 · UX 契约

> **状态**：决策已锁定（2026-09-20）· 实现未开始  
> **关系**：交互面；权限与成功证据仍以 [SITE-OPERATOR-MATRIX.md](./SITE-OPERATOR-MATRIX.md) 为准。排障红线不放宽。  
> **原则**：业务页管证据，值班台管叙事和闸。改交互语义，不整站换皮。

---

## 0. 一句话

9 个业务页仍是操作系统。`/auto-repair-tickets` 从「排障会话」升级为 **值班台**。其它页只做 **agent-aware 深链**，不嵌聊天。

当前债：工作台空状态 / placeholder 已在假装全站 Copilot（「直接提问」「最近为什么一直 FAIL？」），与拍板「无单对话等 S3」冲突。**S2 必须先关掉这句误导文案**，即使早报 API 还没上。

---

## 1. 明确不做

- 全站悬浮聊天球、每页右侧 Copilot
- 把 9 页收成一个对话
- 换 Element Plus / 换 Design tokens / 为 Agent 重做视觉体系
- S3 之前开放无单输入框（可展示只读早报，不可发送全站问题）
- 用对话框一句话触发改脚本、写映射、重启后端
- Collector 工单展示 CDP / 脚本 diff；Repairer 工单展示采集映射 CRUD

---

## 2. 壳层（AppShell）

侧边 9 项 **保留顺序与路由**。只改文案与一个快捷入口。

| 元素 | 现在 | 锁定 |
|------|------|------|
| 导航标签 | 「Agent 工作台」 | 可改为「值班台」；路径仍 `/auto-repair-tickets`（避免外链/书签断裂） |
| `route.meta.description` | 「可以直接对话追问」 | 「早报、排障/采集工单过程；追问默认不改脚本」 |

| QuickActionBar | 环境自检、上传脚本 | **S2** 可加「打开值班台」；**不要**加「问 AI」 |

默认落地页仍是 `/health-tasks`，不改成值班台。

## 3. 值班台布局

现有三列网格保留（`agent-grid`），语义重标。

```text
┌ banner：值班状态 + 计数（排障/采集分列，S4 起）+ 刷新早报 ─┐
│ 左：摘要 + 工单列表     中：时间线/早报     右：本单证据/闸 │
│                         底：输入框（规则见 §5）              │
└────────────────────────────────────────────────────────────┘
```

### 3.1 Banner

- 显示 Watcher 摘要的一句话头条（S2：纯计数，无模型）。
- 计数：处理中 / 排队 / 已修好 / 需人工。S4 起排障与采集 **分色或分列**，禁止混成一个 SOLVED。
- 「刷新」= 拉列表 + 拉早报，不是「再问一次模型」。

### 3.2 左列：不要叫「会话」

| 区块 | 规则 |
|------|------|
| 今日值班摘要 | S2 置顶。结构同矩阵 `site_ops_summary`。每条「需要人看」是 **深链按钮**，不是聊天建议 |
| 筛选 | S4：`全部 \| 排障 \| 采集`。S4 前只有排障单，筛选可先隐藏 |
| 列表行 | 主标题：店铺或任务名；副标题：`kind` + 状态 + 渠道。进行中高亮 |
| 空列表 | 「当前没有进行中的排障/采集单」，**禁止**写「或直接提问」 |

未选中工单时，左列仍显示摘要；中列展示早报全文。

### 3.3 中列：按选中态切换

| 选中 | 中列内容 | 输入框 |
|------|----------|--------|
| 无单 | 早报全文（S2）。S3 前无对话气泡 | **禁用**。placeholder 见 §5 |
| 排障单 | 触发原因 → think / tool / 截图 / **脚本 diff** / **健康复检** → 追问 | 可发送；旁注「不改脚本」 |
| 采集单 | 失败原因 → job / 映射是否存在 / **采集复检**。无 CDP、无脚本 diff | 可发送；旁注「不改映射」 |
| 进入写回合后 | 时间线继续；出现「改脚本」事件必须能点开 diff | 仍默认只读；写操作走右列按钮 |

健康复检 PASS / 采集复检 PASS 在时间线里用不同标签（`健康复检` vs `采集复检`），避免 SOLVED 语义混用。

### 3.4 右列：证据 + 角色 + 闸

始终展示当前 **角色徽章**：Watcher / Repairer / Collector / SRE。

| 工单 kind | 右列必显 | 右列禁显 |
|-----------|----------|----------|
| 无单 | 早报时间窗 `as_of`、深链列表 | CDP、diff、token（可无） |
| `auto_repair` | 状态、店、CDP、健康任务、唤起次数、usage、脚本 diff、复检 | 采集映射编辑 |
| `cookie_sync` | 状态、task、job、映射是否存在（只读）、采集复检 | CDP、脚本 diff、「进入排障」 |

闸按钮只出现在右列或 Banner，不出现在输入框里：

| 按钮 | 角色 | 何时可见 | 交互 |
|------|------|----------|------|
| 进入排障回合 | Repairer | 本排障单 RUNNING/可写 | 二次文案：将允许改本单脚本；RISK 单不出现此按钮 |
| 重派补采 | Collector | 有映射且未关单 | 一次确认即可（现有采集修复 API） |
| 回收停滞运行 | SRE | 用户从运行页深链过来，或摘要指出卡死 | **确认框**，列出将释放的 profile 锁 |
| 重启后端 | SRE | 明确运维上下文 | **确认框**（不可逆、服务会中断）→ 成功条件是事后 health 探活指示 |

无确认记录不得调用对应工具。确认框必须写清后果，不能只写「确定」。

## 4. 业务页：agent-aware 深链

不改各页主表格结构。只在 **失败/异常行** 和必要时页头加出口。

| 页面 | 出口 | 落到值班台 |
|------|------|------------|
| `/health-tasks` | 修复 FAIL/EXCEPTION/RISK 后，若已有排障单：链「看排障」 | `?ticket=<id>` 或 `?code=` |
| `/cookie-sync-tasks` | 无映射 / job 失败 / 复检失败：链「看采集单」；映射 CRUD **留在本页** | 采集 kind 工单 |
| `/script-runs` | 卡死 RUNNING：链「去值班台（回收）」 | 打开 SRE 确认，不自动杀 |
| `/profiles` | 持锁过久：链值班台看占用工单 | 只读解释 |
| `/environment` | 自检红：链值班台 SRE 只读解释 | 无重启按钮在本页也可保留现有「执行自检」 |
| `/logs` | 最近失败：可选「在值班台查看关联单」 | 有 ticket 才显示 |

深链约定：只用已存在的 `path + query`。Agent 与前端都 **不得发明** 不存在的页。早报条目同样遵守。

从值班台跳到业务页用现有筛选/keyword（如 `/health-tasks?keyword=店铺`），能打开对应行即可，不强制新做高亮协议；若做高亮，用 query，不要改全局状态总线。

## 5. 输入框与文案（分切片强制）

追问默认不改脚本，必须在 UI 上可见，不能只写在 SOP。

| 切片 | 无单 placeholder | 有单 placeholder | 发送 |
|------|------------------|------------------|------|
| **现在～S2** | 「全站问答尚未开放。请先打开一张工单，或查看上方早报。」 | 「追问这张工单（不改脚本），例如：为什么复检失败？」 | 无单 **禁用**；有单可发 |
| **S3** | 「问今天的运行情况（只读）。改脚本请打开排障单并点「进入排障回合」。」 | 同左列 kind 切换旁注 | 无单可发，工具箱 = Watcher |
| **S4** | 同 S3 | 采集单：「追问本采集任务（不改映射）」 | 采集单走 Collector 只读+重派按钮 |
| **S5** | 同 S3 | 若涉及重启：输入框仍只读解释，重启走确认按钮 | 对话里说「重启」只允许生成确认卡，不直接执行 |

空状态文案禁止：

- 「或直接提问」
- 「问 Agent：最近为什么一直 FAIL？」
- 「会话」作为左列标题（改为「工单」或「值班」）

进度文案：

| 状态 | 排障单 | 采集单 |
|------|--------|--------|
| SOLVED | 已修好（健康复检 PASS） | 已恢复（采集复检 PASS） |
| NEED_HUMAN | 已停手，需要人工 | 无映射或补采失败，去映射页处理 |
| RUNNING | Agent 正在处理这张排障单 | Agent 正在处理这张采集单 |

## 6. 角色切换（人怎么感觉到）

同一时刻中列+右列只表现 **一套** 角色。切换来源：

1. 未选单 → Watcher  
2. 选中排障单 → 默认只读 Repairer 追问；点「进入排障回合」才露出写工具（RISK 永不露出）  
3. 选中采集单 → Collector  
4. 点 SRE 闸（回收/重启）→ 确认框期间角色显示 SRE，确认结束回到进入前状态  

徽章用现有 `el-tag` 即可，不必新设计系统。

## 7. 与切片的验收（UX）

| 切片 | 必须可见 | 失败判据 |
|------|----------|----------|
| S0 | 无 UI 义务 | — |
| S2 | 关掉无单发送；左列不叫会话；早报计数可对页面；「打开值班台」可选 | 仍能不选单发出全站问题 |
| S3 | 无单 Watcher 问答；角色徽章；追问旁注「不改脚本」；问改脚本被拒有可见回复 | 无单问答改了脚本或调了 CDP |
| S4 | 筛选排障/采集；采集单无 diff/CDP；SOLVED 文案分两种复检 | 采集 SOLVED 写成健康复检 PASS |
| S5 | 重启/回收确认框；确认后 health 探活指示 | 对话一句话重启成功 |

视觉回归：值班台仍用现有 tokens（`--color-surface` / `--radius-lg` 等），三列滚动行为保持（页面不随聊天撑出整页滚动条）。
