# 项目运转记忆（全局）

> 给 Agent 的系统常识。细节以代码与 `docs/Product-Spec.md` 为准；此处只保留排障高频事实。

## 产品一句话

单机 Windows 运维台：保证下游采集依赖的电商/内容平台 **Session/Cookie 可用**。  
外部表 `ods_cookie_playwright` 只按既有列读写，不重构表结构。

## 两条业务闭环（不要搞混）

1. **健康检测任务** → 失败可跑 **本机 Playwright 修复脚本** →（FAIL 后）**你（Agent）**  
2. **Cookie 采集任务** → 同事 **浏览器扩展** 补 cookie（你默认不接管）

## 关键路径

| 路径 | 含义 |
|------|------|
| `backend/` | FastAPI 编排、调度、工单 |
| `frontend/` | 运维 UI |
| `runtime/scripts/` | 维护脚本实体（你可按 SOP 改并落盘） |
| `runtime/profiles/` | 浏览器 user-data 目录库 |
| `runtime/artifacts/` | 单次运行/工单产物 |
| `runtime/logs/` | 服务与运行日志 |
| `docs/agent/` | 你的手册与记忆 |

## 生产运行

- 后端生产入口：计划任务 `SessionBackend-Interactive` → `run_server.py`，常见端口 **8081**  
- 需要交互桌面会话（有头 Chrome / CDP）  
- 平台 UI 无登录鉴权（内网）；扩展 API 用 `X-API-Key`

## 状态与对象（排障相关）

- **HealthTask**：检测配置 + 可选自动修复绑定（脚本 + 目录）  
- **ScriptRun**：一次脚本执行；你多在其 **FAIL** 之后入场  
- **ProfileRegistry**：目录资产；**你工作期间必须占有该目录锁**  
- **AutoRepairTicket**：自动排障工单；你的过程事件挂在这上面给前端看  

## 成功标准（再强调）

健康检测 **复检 PASS** 才算修好。

## 红线摘要

- 不自动过人机验证  
- 不删 Profile 目录  
- 不改 backend core / .env  
- 日志与记忆脱敏  

## 并发

- 不同 Profile 目录可并行多个 Agent/修复  
- 同一 Profile 必须串行  
- 改同一脚本文件时需文件级互斥  

## 常见失败模式（通用）

- 活动弹窗/协议更新遮罩  
- 登录态掉了但脚本仍走旧选择器  
- 页面改版导致 locator 失效  
- 超时过短 / 网络抖  
- 真风控（应 NEED_HUMAN）
